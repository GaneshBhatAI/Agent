# Security Guidelines & Hardening

Security is paramount when orchestrating remote execution across enterprise infrastructure.

---

## 1. Zero-Trust Machine Authentication

- **Single-Use Registration Tokens**:
  - Worker machines cannot register without an active, unexpired registration token generated by an authenticated administrator in the Control Room.
  - Registration tokens are invalidated immediately upon first handshake.
- **Machine Agent Tokens**:
  - Each registered machine is assigned a cryptographically secure 256-bit `agent_token`.
  - Machine tokens are hashed (HMAC-SHA256) before storage in the database.
  - Every outbound agent request (`/api/agent/*`) validates `X-Machine-Id` and `X-Agent-Token` headers.

---

## 2. Command Execution Safety (No `shell=True`)

- **Strict Argument Vector Execution**:
  - The execution engine **never** concatenates raw user strings into shell commands.
  - All script invocations use controlled argument arrays:
    ```python
    subprocess.Popen([venv_python, script_path, *parameters], ...)
    ```
- **Path Traversal Prevention**:
  - Entry points are validated to guarantee they remain strictly inside the isolated workspace folder.
  - Arbitrary OS commands or system utilities cannot be launched directly via the UI.

---

## 3. Credential Protection & Secret Masking

- **AES-256 Symmetric Encryption**:
  - GitHub tokens, API keys, and sensitive environment variables are encrypted at rest using Fernet (AES-128-CBC + HMAC-SHA256).
- **Frontend Isolation**:
  - Plaintext GitHub tokens or backend secrets are never transmitted to browser JavaScript.
- **Real-Time Log Masking**:
  - The Agent's `LogManager` scans all stdout/stderr output lines for passwords, tokens (`ghp_...`), and API keys, replacing them with `[REDACTED]` before broadcasting to the Control Room.
